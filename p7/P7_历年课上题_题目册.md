## 公共说明

每题均以已经完成中断异常支持的五级流水线 CPU 为基础。基础指令和顶层端口依所用课程版本保留；旧版指令较多，新版较少，不把某一年的基础指令数量当成全部年份的要求。较新的课下任务已经包含 syscall，练习 Q01 时可直接复查已有实现。

复位 PC 为 0x3000，普通异常入口为 0x4180；Q06 改变异常入口。数据存储器 DM 的字节地址为 0x0000 至 0x2fff，指令存储器 IM 为 0x3000 至 0x6fff。Timer0 为 0x7f00 至 0x7f0b，Timer1 为 0x7f10 至 0x7f1b。较新版本还提供 0x7f20 至 0x7f23 的外部中断响应地址。加入访问限制不等于扩大原有可访问范围，地址空洞仍按课下规则报错。

GRF 是 32 个 32 位通用寄存器；DM 按字编号，字节地址 address 对应 DM[address[31:2]]。SR、Cause、EPC 分别对应 CP0 的 12、13、14 号寄存器。CP0[n] 表示编号为 n 的寄存器，不是 GRF[n]。源值均取本条指令成功提交之前的值；写 GRF[0] 丢弃。默认所有地址比较都按无符号数进行。

RTL 是行为定义，不是一份可直接粘贴的完整模块。ExcCode 为当前指令已经收集的 5 位异常码，初值为 0；各题只在没有更高优先级异常时添加自己的异常。is_load、is_store、is_lw 等是译码得到的指令类别信号，含义按名称和各题描述确定。访存公共信号 address 为 32 位字节地址，bytes 为 33 位无符号访问长度，取 1、2、4；其他局部变量在代码中声明，不使用额外的数学缩写或抽象异常调用。

SR[15:10] 是中断屏蔽位，SR[1] 是 EXL，SR[0] 是 IE。Cause[31] 是 BD，Cause[15:10] 是 IP，Cause[6:2] 是异常码。下面给出各题共用的请求与保存规则，PC 和 BD 对应受害指令，不是取指级当前正在读取的指令。

```verilog
wire interrupt_request;
wire exception_request;
wire Req;
assign interrupt_request = SR[0] && !SR[1]
                         && (|(HWInt & SR[15:10]));
assign exception_request = !SR[1] && (ExcCode != 5'd0);
assign Req = interrupt_request || exception_request;

Cause[15:10] <= HWInt;
if (Req) begin
    SR[1] <= 1'b1;
    Cause[31] <= BD;
    Cause[6:2] <= interrupt_request ? 5'd0 : ExcCode;
    EPC <= BD ? PC - 32'd4 : PC;
    PC <= 32'h00004180;
end
```

复位优先于以上处理；复位 SR、Cause、EPC 为 0，Q05 另改 SR 的复位值。代码只展示相关字段，不能用它整体覆盖本来需要保留的其他字段。异常不由 IE 屏蔽；有效中断与异常同时到达时，按这里的历史课程约定优先响应中断。硬件保存 EPC 时保留真实地址，不擅自清除低两位。

Req 有效时，受害指令和更年轻指令不得写 GRF、DM、外设或本题新增寄存器；更老指令应完成。不能因统一清流水线而丢失本周期 W 级中更老指令的写入。停止年轻乘除指令启动，同时保留按课程规定已经成功启动的较老乘除运算。

普通分支和跳转有一个延迟槽，无论分支是否成立，槽内受害指令均设置 BD。eret 没有延迟槽：从 EPC 恢复执行，按实现时机清 EXL，不能执行 eret 后顺序取到的指令。软件决定修改 EPC 跳过异常或消除中断源，硬件不自动给 EPC 加 4。暂停产生的空泡仍应携带用于中断定位的正确 PC、BD。

各题主要练习用户态正常代码中的异常。未有明确原题说明的异常嵌套、handler 再次违规、非法修改只读 CP0 寄存器等情形，不新增猜测规则。题内列出的例子是据题义计算的练习例子，不是宣称已经运行过的 CPU 仿真结果。

## Q01 syscall

题源：S01、S02。2020 秋季上机总结记载新增 syscall；2021 仓库另记第二次上机的同类题，未核实两者属于相同场次。

编码：标准简化形式 `000000 00000000000000000000 001100`，即 0x0000000c。原历史题面的非零 code 字段范围未取得；本册练习使用 code 为 0。

格式：`syscall`。

描述：执行此指令时产生系统调用异常，异常码为 8。CPU 负责记录异常并进入异常处理入口，不按 GRF[2] 的值替用户程序打印、读入或退出。

操作：

```verilog
if (ExcCode == 5'd0 && is_syscall)
    ExcCode = 5'd8;
```

其他：按公共说明提交异常，不写通用寄存器或内存。取指地址异常优先于识别到的 syscall。S02 的“当作 RI”用于说明检测和流水方式，不能据此把系统调用的异常码写成 RI 的 10。S01 未保存原编码和完整题面，本题采用标准 syscall 行为补齐。

例子：PC=0x3004、BD=0 时，响应后 EPC=0x3004、Cause[6:2]=8；若本条在 PC=0x3004 的延迟槽，EPC=0x3000、BD=1。这里仅指没有同时发生有效中断的情形。

实现注意：清除这条指令原本可能误生成的写控制，但保留随指令流水的 PC、BD 和异常码。不要将 syscall 清成一条完全丢失定位信息的 nop。

## Q02 teq

题源：S02。作者的 2021 仓库在“P7 上机”下记录 TEQ 和异常码 13，具体考试日期未给出。

编码：采用标准 TEQ 的 code=0 形式 `000000 rs rt 0000000000 110100`。历史回忆未附原平台编码，不能将该标准补全称为原编码。

格式：`teq rs, rt`。

描述：若两个源寄存器的 32 位值完全相等，产生 Trap 异常，异常码为 13；不相等时正常顺序执行。两种情况下均不写通用寄存器和内存。

操作：

```verilog
if (ExcCode == 5'd0 && GRF[rs] == GRF[rt])
    ExcCode = 5'd13;
```

其他：源寄存器值须经过正常的转发或暂停处理。rs、rt 可以相同，也可以为 0。即使在译码级比较，也要将异常信息跟随受害指令传递，不能越过更老的指令立即修改 CP0。

例子：rs 与 rt 都是 0xffffffff 时触发；0x80000000 与 0x00000000 不触发。`teq $0, $0` 必触发，不因寄存器编号为 0 而忽略读取。

实现注意：这条指令有两个源寄存器，没有目的寄存器。不要因为使用比较器或借用 R 型运算类别而误开启 RegWrite。

## Q03 tltiu

题源：S03、S04、S05；标准编码和比较方式由 S13 核对。属于 2021 秋季课上记录，作者未给单场考试日期。

编码：`000001 rs 01011 immediate16`。opcode 为 REGIMM 的 000001；S03 页面写成 000000，与名称及指令手册矛盾，本册采用校正值。

格式：`tltiu rs, immediate`。

描述：先将 16 位立即数符号扩展至 32 位，再把扩展结果和 rs 都按无符号数比较。rs 严格小于扩展结果时产生 Trap 异常，异常码为 13，否则顺序执行。不写通用寄存器。

操作：

```verilog
reg [31:0] immediate32;
immediate32 = {{16{immediate[15]}}, immediate};
if (ExcCode == 5'd0 && GRF[rs] < immediate32)
    ExcCode = 5'd13;
```

其他：名称中的 u 指无符号比较，不表示立即数零扩展。只有 rs 是通用寄存器源，编码中的 01011 是子操作码，不能把它当成 rt 源或目的。

例子：immediate=0xffff 时扩展为 0xffffffff，rs=0xfffffffe 触发，rs=0xffffffff 不触发。immediate=0x0000 时任何 rs 都不触发。

实现注意：若复用立即数运算类别，保留 rs 的冒险处理，同时关闭通用寄存器写入；取指异常仍优先。

## Q04 kernel space 内核地址空间

题源：S06、S09。2022-12-06 平台存档，题目编号 954-1064，名称 P7_L4_kernel_space。

编码：不增加指令，修改取指、load、store 的权限检查。

格式：沿用原有指令格式。

描述：SR[1]=0 为用户态，SR[1]=1 为内核态。0x0000 至 0x417f 为用户地址空间，两种模式都可按原规则访问。0x4180 至 0x7fff 为内核地址空间，用户态取指或读数据产生 AdEL，用户态写数据产生 AdES。

操作：下列代码补充原有地址检查；其中 address 为原访存指令计算出的字节地址。

```verilog
if (ExcCode == 5'd0 && !SR[1]
    && PC >= 32'h00004180 && PC <= 32'h00007fff)
    ExcCode = 5'd4;

if (ExcCode == 5'd0 && !SR[1]
    && address >= 32'h00004180
    && address <= 32'h00007fff) begin
    if (is_load)  ExcCode = 5'd4;
    if (is_store) ExcCode = 5'd5;
end
```

其他：第一段针对取指，第二段针对访存，在流水实现中分别与原检查合并，不在同一条非访存指令上使用无意义的 address。用户态访问内核 IM 产生的取指 AdEL 优先于该处读出的指令可能产生的 RI、syscall 或 Ov。内核态仍保留对齐、合法地址和外设只读寄存器等原有检查。

例子：用户态执行 `lw $t0, 0x7f00($0)`，应进入 0x4180；在 handler 内读取 Cause，单独此次异常对应数值 0x00000010。handler 内再执行同样的 Timer0 读取，不因内核空间限制而报错。

实现注意：判断模式必须对应被检查指令执行前的正确 SR 值。异常入口的指令不能继续沿用异常发生前取指时的旧用户态标记而反复报错；eret 的返回目标也不能沿用旧内核态放行。

## Q05 privileged instruction 特权指令

题源：S07。2022-12-13 平台存档，题目编号 962-1062，名称 P7_L3_privileged_instruction_2022。

编码：不增加指令，改变 mfc0、mtc0 的执行权限。

格式：`mfc0 rt, rd`、`mtc0 rt, rd`。

描述：在 SR[28] 增加 CU0。内核态允许执行 mfc0、mtc0；用户态只有 CU0=1 时允许。用户态 CU0=0 时，这两条指令产生 RI，异常码为 10，且不能产生原本的寄存器读写效果。复位 SR=0x10000000。

操作：

```verilog
if (ExcCode == 5'd0 && (is_mfc0 || is_mtc0)
    && !SR[1] && !SR[28])
    ExcCode = 5'd10;

if (!Req && ExcCode == 5'd0) begin
    if (is_mfc0) GRF[rt] <= CP0[rd];
    // mtc0 仍按原 CP0 可写字段写入。
end
```

其他：本题只明确约束 mfc0、mtc0，不擅自扩展到 eret。原文“CU1 为 1”按同段定义解释为 CU0。SR 的读回必须保留第 28 位，不能仍只实现原来的低位有效域。

例子：复位后用户态先执行 `mtc0 $0, $12`，这条指令按写入前 CU0=1 的状态允许执行，并把 CU0 清零。紧接的 `mfc0 $1, $12` 报 RI；handler 中读取 Cause 应得到 0x00000028，忽略 IP、BD 等其他字段时成立。

实现注意：处理“前一条 mtc0 修改 SR、后一条访问 CP0”的依赖。不能让后一条读取尚未更新的 CU0，也不能用本条写入后的 CU0 否决本条本来合法的 mtc0。

## Q06 EBase register 可修改的异常入口

题源：S08。2022-12-20 平台存档，题目编号 970-1061，名称 P7_L2_EBase_register_2022。

编码：沿用 mfc0、mtc0。CP0 15 号寄存器在本题中用作 32 位 EBase。

格式：`mfc0 rt, $15`、`mtc0 rt, $15`。

描述：EBase 保存异常和中断处理入口，可以用 mfc0 读取、mtc0 写入。响应任何异常或有效外部中断时，跳到 EBase 中的地址。复位 EBase=0x4180。EPC 和 Cause 的保存方式沿用公共说明。

操作：下列写入与入口选择替代本题的对应公共动作。

```verilog
if (!Req && is_mtc0 && rd == 5'd15)
    CP0[15] <= GRF[rt];

if (!Req && is_mfc0 && rd == 5'd15)
    GRF[rt] <= CP0[15];

if (Req)
    PC <= CP0[15];
```

其他：按题面使用全部 32 位，不套用真实 MIPS EBase 的部分位域和掩码。本册用于练习的入口均保证为合法、对齐且已有 handler 的指令地址；原存档没有给出非法 EBase 的完整处理规则。

例子：先向 EBase 写入 0x4184，再执行地址 3 的 lw 触发 AdEL，应从 0x4184 开始执行；0x4180 处的 handler 第一条不能提前执行。

实现注意：更新所有异常入口来源，包括 IFU 和清流水线时写入的 PC 定位信息，不只改最外层 PC 选择器。先前成功的 EBase 写入必须对紧随的异常生效；若中断恰好撤销正在写 EBase 的 mtc0，则使用撤销前的入口。

## Q07 withdraw 撤销最近一次 sw

题源：S10、S11。2024 第一次 P7 上机回忆，两位作者相互补证，未取得平台题面。

编码：0x04000000，即 `000001 00000000000000000000000000`。这是回忆明确给出的唯一合法编码，不能仅检查 opcode 就把同 opcode 的任意指令当成 withdraw。

格式：`withdraw`。

描述：在 CP0 增加 4 个 32 位寄存器：18 号存允许撤销地址的上界，19 号存下界，20 号存最近一次成功 sw 的字节地址，21 号存该次 sw 写入之前的旧整字。4 个寄存器均允许 mfc0 读取，只有 18、19 号允许 mtc0 写入。

成功执行 sw 时更新 20、21 号，并记录已经出现过成功的 sw。withdraw 在尚无成功 sw 时无操作；否则检查最近地址是否位于下界包含、上界不包含的区间中。在区间内则恢复旧整字，在区间外产生 AdES，异常码为 5。

操作：先展示成功 sw 的附加行为，再展示 withdraw。两段均使用公共说明中的请求判断。

```verilog
reg has_sw; reg [31:0] old_word;
if (is_sw && ExcCode == 5'd0 && !Req) begin
    old_word = m_data_rdata;
    CP0[20] <= address;
    CP0[21] <= old_word;
    has_sw <= 1'b1;
end
if (is_withdraw && has_sw && ExcCode == 5'd0) begin
    if (CP0[20] < CP0[19] || CP0[20] >= CP0[18])
        ExcCode = 5'd5;
end
if (is_withdraw && has_sw
    && ExcCode == 5'd0 && !Req)
    DM[CP0[20][31:2]] <= CP0[21];
```

其他：m_data_rdata 取原 sw 写入前、对应其地址的整字读数，不能从更改写地址后的总线上误取。练习补全：复位新增寄存器和 has_sw 为 0；上下界字对齐，按 0 <= 下界 <= 上界 <= 0x3000 构造。用于建立撤销记录的 sw 只访问 DM，外设 sw 是否建立记录不作为本册测试要求。

S10 一处把上下界关系写反，但同文核心条件及 S11 均为 19 号下界、18 号上界，本册据此整理。回忆没有完整说明连续 withdraw 的记录消耗：本册约定 withdraw 不更新 20、21 号、不清 has_sw；没有新 sw 时，连续撤销恢复同一旧值。此项是练习补全，不能视作已核实原题规则。

例子：原 DM[0x100/4]=0x11223344，成功 sw 写成 0xaabbccdd 后，应保存地址 0x100 和旧值 0x11223344。区间为 [0x100,0x104) 时 withdraw 恢复成功；若把上界改为 0x100，则该地址不在区间内，报 AdES。

实现注意：报错或被中断撤销的 sw 不更新记录。sb、sh 不按本册规则建立 sw 记录。withdraw 的恢复写也受 Req 取消，不得在同一周期一边进入 handler 一边恢复内存。

## Q08 Watch Exception 指令和数据地址监视

题源：S12。2024 第二次 P7 上机回忆，未取得平台题面。

编码：不增加指令。新增 CP0 18 号 WatchLo、19 号 WatchHi，均为完整 32 位寄存器，允许 mfc0、mtc0 读写。

格式：沿用原有指令格式。

描述：WatchLo[31:16] 零扩展后是被监视的指令地址；WatchLo[15:0] 零扩展后是被监视的数据字节地址。WatchHi[0] 为总使能，bit1 使能 store 监视，bit2 使能 load 监视，bit3 使能 PC 监视。

总使能和 PC 监视均开，且当前指令 PC 命中时，产生 IMWatch。总使能和对应 load/store 监视开，且实际访问的字节范围包含被监视的数据字节时，产生 DMWatch。两者异常码均为 23。

操作：IMWatch 检查放在取指地址合法性检查之后、译码及运算异常之前。

```verilog
reg [31:0] watched_pc;
watched_pc = {16'b0, CP0[18][31:16]};
if (ExcCode == 5'd0 && CP0[19][0] && CP0[19][3]
    && PC == watched_pc)
    ExcCode = 5'd23;
```

DMWatch 检查放在原有访存 AdEL、AdES 判断之后。bytes 为本条 load/store 实际访问的字节数，字、半字、字节分别为 4、2、1。

```verilog
reg [32:0] first_byte, last_byte, watched_byte;
reg monitor_access;
first_byte = {1'b0, address};
last_byte = first_byte + bytes - 33'd1;
watched_byte = {17'b0, CP0[18][15:0]};
monitor_access = (is_store && CP0[19][1])
              || (is_load && CP0[19][2]);
if (ExcCode == 5'd0 && CP0[19][0] && monitor_access
    && first_byte <= watched_byte
    && watched_byte <= last_byte)
    ExcCode = 5'd23;
```

其他：本册整理的异常顺序为取指 AdEL、IMWatch、指令本身更晚发现的异常；对于数据访问，原有 AdEL/AdES 优先于 DMWatch。原回忆在 DM 段写成 IMWatch，并出现 Watch[1]、[16:0]、[32:2] 等笔误，本册按其寄存器定义和字节范围描述解释。若需严格复刻被笔误影响的原平台行为，现有回忆不足以最终确认。

练习补全：复位两个新增寄存器为 0。WatchLo 的数据地址不要求对齐；mfc0 读取全部 32 位，不能只实现实际参与匹配的位。bytes 和地址范围运算使用足够位宽，避免最后一个字节溢出回绕。

例子：被监视数据地址为 0x101 时，地址 0x100 的 lw 或 sw 命中，地址 0x100 的 lb 不命中，地址 0x101 的 lb 命中。若 lw 地址本身不对齐，则按原有规则先报 AdEL。

实现注意：处理 mtc0 写 WatchLo/WatchHi 后紧跟被监视指令的依赖。IMWatch 命中乘除指令时，不能让该指令提前改变 HI/LO、Busy 或留下之后会提交的计算结果；只在 M 级取消普通写回是不够的。

## Q09 Memory Limitation 内存访问限制

题源：S12。2024 第三次 P7 上机回忆，未取得平台题面。

编码：不增加指令。新增 CP0 18 号 LowerLimit、19 号 UpperLimit，均为 32 位，允许 mfc0、mtc0 读写。

格式：沿用原有指令格式。

描述：18、19 号的低 16 位分别零扩展为限制区间的下界和上界，区间为 [下界,上界)。两寄存器高 16 位中 1 的总数为奇数时，该区间只读，写入报 AdES；为偶数时，该区间只写，读取报 AdEL。

只要本条访问涉及的任意字节与限制区间相交，就要应用限制。下界等于上界表示空区间，不限制任何访问。题源保证下界不大于上界，二者均在 0x0000 至 0x3000 之间，未保证对齐。

操作：在原有地址合法性、对齐检查之后执行。bytes 取 1、2、4。

```verilog
reg [32:0] first_byte, after_last, lower, upper;
reg read_only;
first_byte = {1'b0, address};
after_last = first_byte + bytes;
lower = {17'b0, CP0[18][15:0]};
upper = {17'b0, CP0[19][15:0]};
read_only = ^{CP0[18][31:16], CP0[19][31:16]};

if (ExcCode == 5'd0 && lower < upper
    && first_byte < upper && after_last > lower) begin
    if (is_store && read_only)  ExcCode = 5'd5;
    if (is_load && !read_only)  ExcCode = 5'd4;
end
```

其他：归约异或直接计算这 32 位中 1 的总数的奇偶，是 Verilog 运算符。练习补全：复位两个新增寄存器为 0。限制范围只覆盖 DM；其他地址仍遵守原有规则，不因为区间设置而获得新的访问权限。

例子：只读区间为 [0x101,0x103) 时，0x100 处的 sw 覆盖到受限字节，应报 AdES；0x100 处的 sb 不与区间相交，应正常写。把上下界设成相同值，即使高位奇偶为偶数，load 也不受本题限制。

实现注意：不能仅检查访问起始地址。用 33 位计算右开端点，避免 address+4 的回绕。较老 mtc0 对上下界或奇偶位的修改，应对紧随的内存访问生效。

## Q10 monitor 监视 sw 可写区间

题源：S14。作者文章标注 2025-12-18，2026-02 更新，分别记载第一次和第二次上机；未给出这两场的具体考试日期。

编码：回忆仅确认 opcode=011110 及 rt、rd 两个字段。为便于本册练习，补成 `011110 00000 rt rd 00000000000`；中间 rs 位置和低 11 位取 0 是练习编码，不声称为原平台完整编码。

格式：`monitor rt, rd`。

描述：新增 CP0 18、19、20 号寄存器，分别保存 DMboundaryHI、DMboundaryLO、DMEnable，复位均为 0。它们允许 mfc0 读取，仅允许 monitor 写入；mtc0 写这三者无效果。monitor 写原 CP0 12 至 15 号无效果。

monitor 修改上界后必须仍不小于旧下界，修改下界后必须仍不大于旧上界；不满足则不写入，并报 AdES。写 20 号没有这项大小限制。DMEnable 高 16 位中 1 的个数严格大于低 16 位中 1 的个数时开启监视，否则关闭。

监视开启时只检查 sw，要求写入的全部 4 个字节均落在 [下界,上界) 内，否则报 AdES。sb、sh 不受本题新增监视影响，但仍受原有地址检查约束。

操作：先判断 monitor 的写入合法性。

```verilog
if (is_monitor && ExcCode == 5'd0) begin
    if (rd == 5'd18 && GRF[rt] < CP0[19])
        ExcCode = 5'd5;
    if (rd == 5'd19 && GRF[rt] > CP0[18])
        ExcCode = 5'd5;
end
if (is_monitor && !Req && ExcCode == 5'd0) begin
    if (rd == 5'd18 || rd == 5'd19 || rd == 5'd20)
        CP0[rd] <= GRF[rt];
end
```

再对 sw 增加检查。以下仅在原有访存检查通过后执行。

```verilog
integer i;
reg [4:0] high_ones, low_ones;
reg [32:0] last_byte;
high_ones = 5'd0;
low_ones = 5'd0;
for (i = 0; i < 16; i = i + 1) begin
    high_ones = high_ones + CP0[20][i + 16];
    low_ones = low_ones + CP0[20][i];
end
last_byte = {1'b0, address} + 33'd3;
if (is_sw && ExcCode == 5'd0 && high_ones > low_ones
    && ({1'b0, address} < {1'b0, CP0[19]}
        || last_byte >= {1'b0, CP0[18]}))
    ExcCode = 5'd5;
```

其他：不能把两个 16 位数直接比较来代替数 1。上下界比较按无符号数，计数器至少 5 位以表示 16。回忆没有写明 monitor 访问其他未列编号的规则，本册只练习 12 至 15、18 至 20 号，不补造其余编号的效果。

例子：DMEnable=0x80000001 时两半区均只有 1 个 1，监视关闭；0x00030001 时高半区 2 个、低半区 1 个，监视开启。范围 [0x100,0x104) 允许 0x100 的 sw；范围 [0x100,0x103) 不允许。上下界相等且监视开启时，没有任何 sw 能让 4 个字节全部落入空区间。

实现注意：监视条件与 Q09 相反：Q09 检查与受限区间相交，Q10 要求 sw 全部包含在允许区间内。monitor 的 rt 需要正常转发；非法写入不能先更新边界，再因异常回滚。

## Q11 Integer Overflow 可控制的溢出检测

题源：S14。与 Q10 同一篇作者记录中的第二次上机题。

编码：不增加指令，修改 add、addi、sub 的异常规则。

格式：沿用 `add rd, rs, rt`、`addi rt, rs, immediate`、`sub rd, rs, rt`。

描述：新增 CP0 18 号 OvCtrl，32 位；19 号 OvBound 保存 16 位无符号阈值，两者复位为 0，可用 mfc0、mtc0 读写。OvCtrl[0] 是检测总开关，bit1 控制 add、addi，bit2 控制 sub。

仅在总开关及本条类别开关均打开时检测：普通 32 位有符号溢出，或者低 32 位运算结果按补码解释的绝对值严格大于 OvBound，任一成立即产生 Ov，异常码为 12。关闭对应检测时，即使普通算术溢出，也保留低 32 位结果正常写回。本题不改变访存地址计算导致的 AdEL、AdES。

操作：先计算结果、普通溢出和结果绝对值，再应用本题开关。

```verilog
reg [31:0] a, b, result, magnitude;
reg normal_overflow, enable_check;
a = GRF[rs];
b = is_addi ? {{16{immediate[15]}}, immediate} : GRF[rt];
result = is_sub ? a - b : a + b;
if (is_sub)
    normal_overflow = (a[31] != b[31])
                   && (result[31] != a[31]);
else
    normal_overflow = (a[31] == b[31])
                   && (result[31] != a[31]);
magnitude = result[31] ? (~result + 32'd1) : result;
enable_check = CP0[18][0]
             && (((is_add || is_addi) && CP0[18][1])
                 || (is_sub && CP0[18][2]));
if (ExcCode == 5'd0 && enable_check
    && (normal_overflow
        || magnitude > {16'b0, CP0[19][15:0]}))
    ExcCode = 5'd12;
```

其他：本段仅用于这三条指令，未响应异常时按原目的寄存器规则写 result。题源保证 OvBound 不大于 0x7fff。对 19 号的高 16 位，回忆没有给出保留规则，本册练习约定写入时只保留低 16 位、读回高 16 位为 0；该约定不是已核实的原平台要求。

原有实现若在 ALU 中无条件先写入 Ov，本题须替换该检测，不能在旧 Ov 后面再添加开关。result=0x80000000 时，其绝对值以无符号 0x80000000 表示，不能在有符号比较中误判为负。

例子：OvCtrl=3、OvBound=10，add 的结果为 10 或 -10 不报错，结果为 11 或 -11 报 Ov；sub 不受本题开关检测。OvCtrl=0 时，0x7fffffff+1 正常写回 0x80000000。若开启 sub 检测，0x80000000-0x7fffffff 虽然低 32 位结果为 1，仍应因普通溢出报 Ov。

实现注意：较老 mtc0 修改 OvCtrl/OvBound 后，紧随的算术指令必须使用新值。若在 E 级检测，可暂停或转发相关 CP0 写入；若推迟判断，必须保证错误结果不先写回或被当成有效结果转发。

## 附录一 历年强测记录与复习检查点

2020 秋季的 S01 记录了旧功能弱测、CP0 与中断异常基础测试、强测和新增 syscall。2021 的 S03 至 S05 记录了功能强测、异常强测、中断强测和一题异常扩展。2022-12-06 的平台考试说明与题目列表可直接核对同样的三类强测和 kernel space。2024 的 S10、S12 记录前四项为功能、冒险、异常、中断强测，第五项为扩展题。题数、必做项和通过条件随年份变化，不能当作本届考试规则。

下面是根据这些历史分类整理的复习范围，不是取得了原强测的隐藏数据，也不计入 11 道题。

功能与冒险：先检查原有 P6 指令，再检查 mfc0 结果参与运算、分支和 store；检查运算、load 给 mtc0 供数；检查 mtc0 写 EPC 后立即 eret。GRF[0]、HI/LO、链接寄存器的旧功能继续保留。

异常：逐一覆盖取指不对齐和越界、未知指令、syscall、add/addi/sub 溢出、各宽度访存不对齐、DM 越界、Timer 的非法宽度访问和只读寄存器写入。原有取指异常不能被更晚的异常覆盖。

中断：分别检查 IE、EXL、各 IM 位的屏蔽；检查有效中断与同步异常同时到达；检查分支成立、不成立时的延迟槽；检查暂停空泡处的中断定位；检查中断到来时取消年轻 store、mtc0 和乘除启动。

外设：Bridge 根据真实地址只向命中的目标发送写使能。外部 interrupt 与两个 Timer 的 HWInt 位序依课程端口约定连接。较新版本由软件写中断响应地址消除中断源，不能把较早年份某份实现中自动写 0x7f20 的方式当作所有年份都通用。

新增寄存器：在每道题独立的 CPU 中检查复位值、读回宽度、写权限、前后依赖和 Req 对写入的取消。Q07 至 Q11 重复使用 CP0 18、19 号是因为题目独立，不能直接合并寄存器含义。

# 接口与预期结果规范

## 端口与环境

唯一顶层为 mips，端口来自 P7提交.zip 中的 mips.v。完整机器可读声明在 protocol/ports.json。

| 信号 | 方向 | 位宽 | 含义 |
|---|---|---:|---|
| clk、reset、interrupt | 输入 | 各 1 | 时钟、同步复位、外部电平中断 |
| macroscopic_pc | 输出 | 32 | 中断受害指令的宏观 PC；此提交接 m_inst_addr |
| i_inst_addr / i_inst_rdata | 输出 / 输入 | 各 32 | 外置指令存储器地址与整字读数 |
| m_data_addr / m_data_wdata / m_data_rdata | 输出 / 输出 / 输入 | 各 32 | 外置 DM 字节地址、写数据、包含该地址的整字读数 |
| m_data_byteen | 输出 | 4 | DM 各字节写使能，bit0 对应最低字节 |
| m_int_addr / m_int_byteen | 输出 | 32 / 4 | 外部中断响应地址和写使能 |
| m_inst_addr | 输出 | 32 | 当前 M 级行为所属指令 PC |
| w_grf_we / w_grf_addr / w_grf_wdata | 输出 | 1 / 5 / 32 | 通用寄存器写回 |
| w_inst_addr | 输出 | 32 | 当前 W 级行为所属指令 PC |

IM 为 4096 个字，地址 0x3000 至 0x6fff。code.txt 下标为 (i_inst_addr-0x3000)>>2。对于范围内未对齐地址，输入仍取包含该地址的整字，CPU 应自行报取指 AdEL；范围外输入 0xffffffff，不能用数组取模将其绕回合法地址。

DM 为 3072 个字，即 0x0000 至 0x2fff，初值全零，小端。m_data_rdata 为 data[m_data_addr>>2]，即包含该字节的整字；范围外回零。不能把 Timer 的读数再从外置 DM 送入，Timer 已在提交的 mips 内实例化，通过 Bridge 处理。

三个硬件中断位为 HWInt[0]=Timer0、HWInt[1]=Timer1、HWInt[2]=interrupt。这里只驱动顶层 interrupt，不直接驱动内部 HWInt，也不替换用户 Timer。

每点初始 reset 持续 3 个上升沿，随后在下降沿释放。reset 时外置 DM 清零，interrupt 初值为 0。时钟示例周期 10 ns，所有周期预算和间隔检查均按上升沿计数。

## 固定序列的比较

expected.json 中的十六进制数为 8 位字符串，不带 0x；reg、byteen、code 为整数。GRF、DM、int 各自是有序数组，分别比较，不能把 M/W 的跨通道先后顺序作为要求，也不能排序、去重或只比较最终值。

1. GRF：在每个非复位上升沿，w_grf_we=1 且 w_grf_addr!=0 时，收集 w_inst_addr、地址和值。对照 grf 数组逐项比较。写 $0 不产生有效寄存器写入，但程序会验证 $0 始终读零。
2. DM：m_data_byteen 非零时收集 m_inst_addr、实际字节地址、byteen。按使能合并写入，核对 value_mask 覆盖的 write_bits 和合并后的 merged_word。未使能字节的总线值不作要求；地址和 byteen 不能忽略。
3. 中断响应：m_int_byteen 非零时收集 m_inst_addr、m_int_addr、byteen，逐项对照 int 数组。响应地址应属于 0x7f20 至 0x7f23。
4. 多余、缺少、重复事件均不接受。有效使能或有效地址/数据出现 X/Z 应报错，不能把未知值自动当零。

final_registers、final_memory、final_cp0、final_hilo 和 exceptions 用于解释与复核。必须通过测试程序的 mfc0、mfhi、mflo 和公开写回端口观察相关效果，不读取 DUT 内部层级来代替功能测试。

完成条件为 case.json.finish_pc 对应的指令在 W 级向 $30 写入 0x0000cafe，同时地址和值都匹配。之后继续采集 12 个周期，检查有无错路或延迟写入。单点总预算为 max_cycles=12000，提前结束或预算内没有完成标记应失败。

B061 至 B080 另有 timing_checks：在指定源值生产写回与 mfhi 写回之间，检查乘法至少 5、除法至少 10 个周期的保守下界。它们用于检出过早解除 Busy 或错误缩短规定占用周期，不要求不同实现有相同总周期数。

## 外部中断注入

interrupts.json 中每条规则只触发一次：第一次在下降沿观察到 (macroscopic_pc & 0xfffffffc)==target_pc 时，将 interrupt 拉高。保持至上升沿接受到中断响应地址的有效写入，再在下一下降沿拉低。进入 handler 本身不等于已经清除外部中断。

测试程序使用 sb $0,0x7f20($0) 响应中断，避免把响应操作误记为 Q07 的普通 DM sw 历史。发生多个中断时，分别按规则再次拉高；原始提交不会被评测端偷偷修改 CP0 使能。

必须检查所有规则确实触发。IE、IM 或 EXL 屏蔽时，输入仍保持高电平，Cause.IP 应继续更新；解除屏蔽后再响应。B217 至 B224 专门检查这一点。

## 基础 MDU 的允许行为

本包基础强测采用公开 P7 教程存档中规定的例外：已经在 E 级启动的受害乘除指令，或已经修改 HI/LO 的受害 mthi/mtlo，在进入中断时可以保留效果。较年轻且尚未启动的 E 级指令仍必须被取消。

B167、B174 各有一条 handler 的 mflo 观察允许读到中断前旧值或受害 mtlo 的已完成值。仅这两条事件在 expected.json 中列 allowed_values，其余字段和事件数仍严格比较；重新执行后的正常主程序结果仍须正确。不得将所有 HI/LO 不一致都忽略。

Q08 的 IMWatch 依题目回忆明确要求受害 MDU 指令不改变状态，该扩展不套用基础 CPU 的此项放宽。

依据：[P7 公开教程存档的中断异常行为规范](https://solor-wind.github.io/2024/01/23/%E8%AE%A1%E7%BB%84P7%E6%95%99%E7%A8%8B/)。采用的具体边界已写进本包；若后续题面另有明确规定，应为该题单独制定数据规范。

## Timer 约束检查

B181 至 B200 使用 expected.json.mode=timer_contract。Timer 运行在真实 clk 上，流水暂停会改变循环次数、受害 PC 和部分计数读数，因此不生成一份假定单周期 CPU 的固定逐条日志。

这些点要求同时满足：

- 按指定次数进入 handler，Cause.ExcCode=0；未实现的 Cause 位与无来源的 IP 位保持零。
- EPC 对齐且落在给定可接受程序区间；BD=1 时 EPC 必须指向真正的分支或跳转。
- 单 Timer 的周期或软件重启场景，连续 handler 入口间隔不得低于 min_handler_gap_cycles；该值采用 preset-16 的保守下界，用于识别错误的连续电平重入。
- read_checks 指定的 Count、Preset、CTRL 读数次数、PC 和范围正确，Count 在启动后确实装载并计数，CTRL 保留位不被保存。
- 只在到达指定中断次数后退出，最终两个 CTRL 都读零，计数标记写入 DM 0x2e00，eret 后的错路标记不得执行。
- 真实 Timer 中断不应生成外部中断发生器的确认写入；最终状态与 expected.json 一致。

不接受只看“程序跑到末尾”就判 Timer 通过的实现。mode 0 包含软件重新启动后再次中断，mode 1 包含自动周期中断；另覆盖双 Timer、IE 屏蔽后放行及 CTRL 的 IRQ 使能。

## 运行中复位

B201 至 B216 的 mid_reset 要求第一次在下降沿命中指定宏观 PC 时再次拉高 reset，保持 3 个上升沿；部分点在复位期间同时保持 interrupt=1，以验证复位优先级。外置 DM 同时清零。第二次释放 reset 后将 interrupt 清零，从 0x3000 重新启动。

第一启动阶段用于制造非零状态或正在运行的 MDU；固定事件序列只比较第二次释放后的完整执行。仍须确认复位确实发生，且复位期间没有有效 GRF、DM 或中断响应写入。第二次启动开头在覆盖通用寄存器之前逐个读出，并读取 HI、LO、SR、Cause、EPC，验证状态已复位。

## 课上题约定与未定义输入

所有扩展题各自独立，CP0 18 至 21 号的含义不能跨题混用。编码采用题目册练习版本，尤其 monitor 只有 opcode、rt、rd 取得历史证据，其余固定零是练习补全。withdraw 连续撤销不消耗记录、OvBound 读回高 16 位为零、未明确复位的扩展寄存器取零等，均沿用题目册明示补全。

没有为除数零、0x80000000/-1 的有符号除法、延迟槽内再次控制转移、handler 再次违规、未说明的只读 CP0 写入等软件约束外行为编造期望值。这些不应与遗漏合法输入混为一谈。

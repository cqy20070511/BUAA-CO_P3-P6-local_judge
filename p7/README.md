# P7 评测数据点

整理日期：2026-11-28。以用户提供的 P7提交.zip 顶层端口为准，按《P7 往年题目册》的练习定义生成。共 488 个独立数据点，所有题之前先安排 224 点基础强测，随后为 11 道课上题各 24 点。

## 数据顺序

| 章节 | 数据点 | 内容 |
|---|---:|---|
| 00_P7基本CPU强测 | B001 至 B224，共 224 点 | 原有指令、冒险、CP0、异常、外部中断、双 Timer、运行中复位 |
| 01_课上考试P7 | Q01 至 Q11，各 24 点，共 264 点 | 题目册中的 11 类扩展，各题独立使用 CP0 编号和编码 |

基础强测包括 204 点固定事件序列和 20 点 Timer 约束检查。固定序列点实际执行 154 至 437 条参考指令，平均 261.9 条；Timer 点包含循环、异步中断、计数器读回及返回检查。两类检查的区别见接口规范。

## 本轮验证结果

- 原始提交的基础 CPU：224/224 通过真实 Icarus 编译与仿真。
- 原始提交已经支持 syscall：另跑 Q01 的 24 点，24/24 通过。
- 故意改错的 RTL 副本：31/31 被同一套基础强测检出。
- 全部 488 点的文件、机器码、意图断言和参考模型复算通过；另完成 16000 组数学边界检查，以及 11 类题目模型故障注入。
- Q02 至 Q11 的 240 点尚未用对应扩展 RTL 实测。它们的预期来自独立指令级模型，不是取原始 CPU 的输出生成。

这些结果说明已列覆盖范围中的检查有效，不能由有限测试证明 CPU 在所有可能程序下都没有错误。未定义行为与软件约束外的情况没有伪造唯一答案，详见规范。

## 每个数据点有什么

- code.txt：4096 个 32 位机器码字，第一行对应 0x3000，含已放到相应地址的 handler。
- program.asm：地址、机器码、汇编操作和标签的完整清单。labelhi、labello、watchpc 是生成器伪操作，旁边机器码可直接装入 IM。
- case.json：题号、目的、重点 PC、完成标记、周期上限、复位计划及检查条件。
- interrupts.json：按宏观 PC 注入外部中断的条件。Timer 点靠提交中的 Timer 产生 IRQ，此文件为空。
- expected.json：机器可读的最终判定依据。包含有序 GRF、DM、中断响应事件，或 Timer 的范围、次数、间隔与最终状态约束。
- 固定序列点另有 expected_grf.log、expected_dm.log，便于人工查看。两处允许取值的事件以 or 分隔，接入时应读取 expected.json 的 allowed_values，不能当成单值日志比较。

DM 初始全零，所有其他数据通过测试程序正常的 store 建立。每点单独复位，测试之间不能沿用 CPU、CP0、HI/LO、Timer 或 DM 状态。

本包提供数据及复核材料。没有修改现有评测机、网页、GitHub 仓库或用户提交的 RTL。11 道扩展题独立使用，不将它们的 CP0 18、19 号定义直接合并。

## 本地校验与重新生成

使用 Python 3.10 或更新版本，仅需标准库：

```text
python tools/check_integrity.py
python tools/validate_data.py
```

第一条核对原包文件 SHA-256，第二条只读测试数据并重新计算模型与边界校验。需要明确重新生成固定数据时，运行 python tools/generate.py；它会重新写入本包的派生 tests、cases.json、problems.json。改动或重新生成后，原包的完整性清单不再用于证明修改后的文件未变。

采集示例按 Verilog 2005 编译，以兼容提交中使用 type 作为标识符的写法。该文件只采集端口；判定实现应严格遵守接口规范和 expected.json，不依赖 CPU 内部命名。

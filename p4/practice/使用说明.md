# P4 加指令练习包

共 14 题、42 组独立程序，编码及操作见 [题目册](./题目册.md)。每道题可以从自己的课下 CPU 单独实现；测试不会混入其他练习题指令。

## 直接开始

1. 选择题号，例如 Q01。按题目册添加 `eam` 的译码与操作。
2. 将 `tests/Q01/basic/code.txt` 复制到你的仿真运行目录，替换用于 `$readmemh("code.txt",...)` 的测试文件。每个 code.txt 都已填满 4096 个字，直接按十六进制读取。
3. 复位后仿真。可用附带的 `mips_tb.v` 替换测试台，顶层接口仅需 `mips(clk,reset)`。它先进行两次同步复位，然后执行 400 个周期。全部用例在 61 个周期以内进入无写入的自循环，400 个周期足够。
4. 保存 CPU 的寄存器、内存写入日志为 `actual.log`。运行目录中的 code.txt 必须是刚才选择的那组；不要只替换源码目录而忘记仿真目录。
5. 对照 `expected.log`，或运行下面的比较命令。

```powershell
.\检查日志.ps1 -Case 'Q01/basic' -Log 'C:\你的仿真目录\actual.log'
```

比较通过后，分别换成同一题的 `edges` 和 `alias_zero` 再测。运行比较脚本不会修改你的 CPU 或日志。

## 每组文件

| 文件 | 内容 |
|---|---|
| code.txt | 可直接加载的 4096 行机器码，包含初始化程序 |
| listing.txt | 当前 PC、机器码、汇编写法，便于逐条定位 |
| expected.log | 应出现的全部寄存器/内存写入事件 |
| expected.tsv | 带执行周期号的同一批期望事件 |
| final_state.json | 最终全部 GRF、非零内存字和停留 PC，便于手工调试 |

basic 是常规功能；edges 包含极值、负偏移或地址边界等；alias_zero 包含源目的编号重合、$0、$31 等。不同题的具体覆盖不同，完整运行规模见 `cases.json`。

初始化都由普通基础指令完成，不需手动预置 GRF/DM。程序末尾的 `beq $0,$0,-1` 是测试结束标记，没有延迟槽，不产生写入。不要把它误认为测试死循环故障。

## 输出约定

```text
@00003000: $1 <= 12345678
@00003004: *00000040 <= 89abcdef
```

允许前面带仿真时间，十六进制可大写。寄存器编号为十进制。内存地址按字对齐，数据是存储后完整字；字节写也按此要求打印。比较脚本会忽略仿真器提示行和尝试写 $0 的行，其他写入必须完全匹配，缺少、额外、顺序错误、X/Z 都不会通过。

此脚本核对 CPU 自己打印的写入日志，不直接探测内部存储元件。请保证日志忠实反映实际写入。日志全通过不等于穷尽了所有可能输入，也不表示已经检查复位时序的全部边界。

## 编码与 MARS

这些练习采用统一分配的练习编码。题目册中列出了每个 op、R 型 funct 和所有固定字段。I 型没有 funct。`instructions.json` 是机器可读编码表。

普通 MARS 不认识这些自定义编码和名字，**无需把 listing.txt 交给 MARS 汇编**。直接使用已生成的 code.txt 即可；listing.txt 只用于阅读和调试。

`make_cases.py` 包含生成器、汇编编码和软件执行模型，需要 Python 3.10 及以上；可以重新生成全部用例。`compare_trace.py` 只比较日志，不生成期望。验证记录见 [验证记录](./验证记录.md)。

## 练习与历史来源

本册以确定的练习规则补齐了历史回忆缺失。Q01 固定扩展方向；Q05 固定为有符号加法不溢出时分支链接；Q06 固定字节筛选及写入规则；Q13、Q14 固定链接与地址边界。编码统一后可以累计实现。原始来源及不确定性仍保存在上一级目录的来源索引和文字回忆存档中。
